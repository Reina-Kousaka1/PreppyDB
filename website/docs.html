PRE-RELEASE DOCUMENTATION

Documentation, with the receipts.

PreppyDB 0.1.0 remains an open development PR. This concise site guide is sourced from PR #1 documentation and does not turn planned or unverified work into a production claim.

Getting started

PreppyDB is described as an embedded-first Rust document database. Build and operate it locally; it is not a Vercel-hosted service.

cargo build --release
./target/release/preppydb-server --data-dir ./data --init-admin admin --init-only

Installation

The pre-release README documents native builds on Linux, macOS and Windows. It does not claim published binaries, images or release downloads. Use the source branch and its operations guide.

Configuration & security

Initialize an administrator with a long secret supplied through the documented environment variable; the source documentation explicitly says there is no default password. Place TLS termination in a reverse proxy where required. Keep tokens and data directories outside this static website.

Security policy ↗

Rust & Lua/Luvit clients

The development branch contains a blocking Rust client crate and a Lua/Luvit client. Consult their source READMEs for exact APIs and compatibility; this website intentionally does not invent SDK installation commands.

Lua/Luvit client guide ↗

HTTP API

The documented /v1 API uses JSON and bearer or session tokens with structured error responses. It is for a locally operated PreppyDB server—not for this site’s browser playground.

API reference ↗

Storage engine & transactions

The branch documents a write-ahead log, checkpoints, CRC32C-protected records, snapshots, recovery and read-committed transactions. Replication, clustering and sharding are expressly not implemented.

Architecture source ↗

Indexes, TTL & backup

Secondary equality/range/unique indexes, TTL expiry sweeps, and integrity-checked backup/restore are documented as implemented in the pre-release branch, with limits in the operations and architecture documents.

Docker & Raspberry Pi / ARM64

The source includes Docker and ARM64 build instructions, but its test guide marks Docker and ARM64 runs as not executed. Treat those paths as instructions to validate in your own environment, not as a qualification claim.
